Skyward 0.3.2 for the Xiaomi 15 Pro (`haotian`), made on the stock recovery
`OS4.0.0.19.XOBCNXM`.

Image: `skyward-v0.3.2-haotian-OS4.0.0.19.XOBCNXM.img`. Check it against
`SHA256SUMS`, then, with the phone in fastboot mode on the slot it runs from:

```sh
sha256sum --check SHA256SUMS
fastboot flash recovery skyward-v0.3.2-haotian-OS4.0.0.19.XOBCNXM.img
fastboot reboot recovery
```

## 这一版改了什么

这一版把上游 `kirklin/skyward` 的 0.3.1 并了进来。上游的改动、以及它们在这台
手机上意味着什么：

### 1. 安全元件服务由 recovery 自己提供

手机的 weaver 把密钥槽存在安全元件里，它通过
`android.se.omapi.ISecureElementService` 要一条到那颗芯片的通道。在系统里这是
某个 app 提供的；recovery 里没有 app，于是以前这条路在 recovery 里走不通。
现在 recovery 自己提供这个服务（新 crate `skyward-omapi`：APDU、通道、以及注册
时用的服务名 `android.se.omapi.ISecureElementService/default`）。对
`haotian` 这种把槽存在芯片里的手机，解锁时少了一个「只有系统才有」的前提。

### 2. 手机自己的按键服务按它自己的分区启动

keymint 这类用钥匙的服务，是哪些程序、怎么启动、要哪些 socket，都由安装好的
系统自己的分区说了算（它的 init 脚本、服务描述、vintf 清单）。现在 recovery
去读那些分区，照着启动，不再把这些写死在 `devices/haotian.toml` 里（新 crate
`skyward-programs` 和 `crates/skyward/src/keys.rs`）。系统更新把这些程序换了
名字或路径之后，仍然跟得上。

### 3. recovery 也能对外提供服务

`crates/skyward-binder` 多了一条路：recovery 自己的对象可以注册进
servicemanager，让手机上的程序调用它（上面那个安全元件服务用的就是这条路）。

### 4. 一个 DNS 不回答就问下一个

解析走的是同一个问题换一个服务器，而不是一直等第一个（`crates/skyward-net/src/dns.rs`）。

### 5. 电池或系统版本读不到时，页面不再退出

读电池、读已装系统的属性失败，现在只是那一条读数没有，页面照常（上游
`2ea0065`）。

### 6. 长日志不再被内核截断

超过一条内核日志记录长度的文本按记录切开分几次写（上游 `cca526b`）。超长的
报错和脚本输出不会再从中途断掉。

### 7. 双系统切换前先按保留的启动分区设好

切换到另一套系统之前，先按保留下来的那套的启动分区设置写一遍，再覆写
（上游 `990abf5`）。

### 8. 工程改动

上游把 workspace 移到了 2024 edition、Rust 1.100.0、resolver 3；把页面的状态
机拆成 27 个模块；让逻辑测试在电脑上跑、lint 针对手机跑；CI 只在 tag 与这次
构建出的版本一致时才发布 release。这个 fork 保留自己的页面
（`crates/skyward-ui/src/app.rs`、`crates/skyward/src/ui.rs`）和自己的全部功能，
只接手上游的工程改动与上面这些修复。并这一版时把 2024 edition 下 clippy 要求
的 `if let` 链（原来的嵌套 `if`）改了过来，并清掉了合并留下的未使用依赖。

## 这一版保留的东西

- **super 镜像**：认 liblp 几何头的整块 super 镜像可以直接刷，不问槽位、快照
  合并中拒绝；写前 discard、4 MiB 一次写、三窗口校验、本地文件直读，每 GiB 往
  内核日志写一行速率。
- **安装不会无限等**：脚本输出镜像进内核日志并在安装页显示；安静 30 秒报一次
  卡在哪；十分钟毫无动静就结束并把报告作为原因；`update-binary` 放在
  `/skyward/run`。
- **解密被拒时说界面语言**：weaver 的节流、错误密钥、重试都变成三种语言的句子。
- **AVB**：`avbctl` 一次改两个槽的 vbmeta（全成或全不成，flock 加写回校验）。
- **返回手势的预测式预览**：手指拉着的时候下面那一页跟着进来，每层留一张。
- **触感**：12–26 ms 的「嗒」，长度跟着强度滑块走，上限是满强度。
- **Wi-Fi**：开机自己连上记住的网络；扫描、连接、忘记、信号显示照旧。
- **界面**：三语、深浅主题、搜索与排序、关机页、OTA 暂停/删除、文件管理、备份
  还原、双系统。插件页与 webview 不在这一支上。

## 怎么确认装上了

```sh
adb shell dmesg | grep -i "recovery up"   # 应为 haotian 0.3.2
```

## This release in English

**Upstream 0.3.1, merged in.** This release brings `kirklin/skyward`'s 0.3.1
into this fork. What it changes on the phone:

**The secure element service is served by the recovery itself.** A phone whose
weaver keeps its slots in a secure element asks
`android.se.omapi.ISecureElementService` for a channel to the chip. In a system
an app serves it; a recovery runs no app, so this path used not to work here.
The recovery now serves it itself (the new `skyward-omapi` crate: APDUs,
channels, and the service name a phone's descriptions expect).

**The programs that use the phone's keys are started as the phone's own
partitions say.** Which programs serve keymint and the rest, how each starts
and which sockets it is handed are read from the installed system's own
partitions rather than written into `devices/haotian.toml` by hand (the new
`skyward-programs` crate and `crates/skyward/src/keys.rs`), so a system update
that renames or moves them is still followed.

**The recovery can serve objects of its own.** `crates/skyward-binder` gained
the other direction: the recovery's own objects register with servicemanager
for the phone's programs to call, which is how the secure element service
above is reached.

**A DNS server that does not answer is passed over.** The next one is asked
instead of waiting on the first.

**A reading that cannot be taken no longer takes the page with it,** and a
message longer than one kernel log record is written as several instead of
being cut off. Switching between two installed systems now sets the boot
partitions against what is kept of them before writing over them.

**Engineering.** Upstream moved the workspace to the 2024 edition, Rust
1.100.0 and resolver 3, split the pages' state machine into 27 modules, runs
the logic tests on a computer and lints for the phone, and publishes a release
only where the tag names the version built. This fork keeps its own pages
(`crates/skyward-ui/src/app.rs`, `crates/skyward/src/ui.rs`) and every feature
its releases added; merging also turned the nested `if`s the 2024 edition's
let-chains let clippy ask about into chains, and dropped the dependencies the
merge left unused.

**Everything this fork's releases have, still here.** A raw super image as a
package of its own, written the way TWRP writes one (discard, 4 MiB writes,
three windows read back, the file read where it lies, a rate line per GiB to
the kernel log); an install that cannot wait for ever, with the script's
output mirrored to the log and a report of where it stalled; refusals at the
unlock page in the page's own language; `avbctl` covering both slots or
neither; the back gesture's preview of the page under the page shown in; a
click of twelve to twenty-six milliseconds whose length follows the slider,
up to the whole strength; a remembered network joined by itself when the
recovery starts; three languages, both themes, the search and the sort, the
power-off page, OTA pause and delete, the file manager, backups and two
installed systems.
