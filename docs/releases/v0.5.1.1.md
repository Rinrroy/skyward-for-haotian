Skyward 0.5.1.1 for the Xiaomi 15 Pro (`haotian`), made on the stock recovery
`OS4.0.0.19.XOBCNXM`.

Image: `skyward-v0.5.1.1-haotian-OS4.0.0.19.XOBCNXM.img`. Check it against
`SHA256SUMS`, then, with the phone in fastboot mode on the slot it runs from:

```sh
sha256sum --check SHA256SUMS
fastboot flash recovery skyward-v0.5.1.1-haotian-OS4.0.0.19.XOBCNXM.img
fastboot reboot recovery
```

## 这一版改了什么

这一版把上游 `kirklin/skyward` 的 0.5.1 并了进来。上游的改动、以及它们在这台
手机上意味着什么：

### 1. 重新创建过 data 分区的备份也能还原了

以前恢复一份备份时，只要手机上的 data 分区在备份之后重新创建过（例如恢复过
出厂设置），这份备份的 data 部分就会被拒绝。现在它照常恢复：备份里的文件写进
现在的分区，应用在内部存储里的目录按现在这套系统的编号重建，其余文件原样放回
（上游 `3179051`）。

### 2. 未加密的 data 分区不再需要密钥服务

手机把 data 分区以明文保存时，恢复模式以前仍然会去开 keymint 才继续。现在这类
手机直接打开分区，密钥服务不在也不影响（上游 `3857f4c`、`7568a50`）；把 data
分区重新创建也不再依赖它（上游 `dc7f769`）。

### 3. 内部存储单独记一项

备份的内部存储（`/data/media`，也就是用户自己的文件）现在在清单里单独记作一项，
不再和 data 分区的文件混在一起（上游 `3179051`），所以在没有 data 分区文件的
情况下也可以只还原内部存储。备份页上它仍和 data 分区一起勾选。

### 4. 安全元件的驱动按手机自己的描述找

NXP 的 weaver 把密钥存在自己的安全元件里，它的驱动和库由手机的系统分区描述；
恢复模式现在照着那份描述找，不再找不到就放弃（上游 `736ea54`）。

### 5. 工程改动

上游把 workspace 更新到了 Rust 1.100 的写法（never 类型、`trim_prefix`、
`trim_suffix`、`bool::toggle`、`Vec::from_fn`），打开了 workspace 级的
`unused_dependencies` 检查，并修了 lp 读回空洞、安装计数两处。这个 fork 保留
自己的页面（`crates/skyward-ui/src/app.rs`、`crates/skyward/src/ui.rs`）和自己
的安装引擎，只接手上游的工程改动与上面这些修复；上游这一版的 15 语言界面、
按分区选择的时区页、super/逻辑分区/sparse 镜像的刷写方式、以及 REDMI K60 Pro
（`socrates`）都不在这一支上。并这一版时，fork 的页面按上游改过的
`skyward-info`、`skyward-crypto`、`skyward-backup`、`skyward-config`、
`skyward-programs` 接口做了对应改动。

### 6. 版本号

这一版是 `0.5.1.1`：前三段是它所在的上游版本，第四段是这个 fork 自己的补丁号，
往后就是 `0.5.1.2`、`0.5.1.3`。它和 `0.3.1.2` 一样是四段号，应用内的更新检查
会把这一版推给现在装着 `0.3.1.2` 的手机。

## 这一版保留的东西

- **super 镜像**：认 liblp 几何头的整块 super 镜像可以直接刷，不问槽位、快照
  合并中拒绝；写前 discard、4 MiB 一次写、三窗口校验、本地文件直读，每 GiB 往
  内核日志写一行速率。
- **安装不会无限等**：脚本输出镜像进内核日志并在安装页显示；安静 30 秒报一次
  卡在哪；十分钟毫无动静就结束并把报告作为原因；`update-binary` 放在
  `/skyward/run`。
- **解密被拒时说界面语言**：weaver 的节流、错误密钥、重试都变成三种语言的句子。
- **AVB**：`avbctl` 一次改两个槽的 vbmeta（全成或全不成，flock 加写回校验）。
- **返回手势的预测式预览**：手指拉着的时候下面那一页跟着进来，每层留一张。
- **触感**：12–26 ms 的「嗒」，长度跟着强度滑块走，上限是满强度。
- **Wi-Fi**：开机自己连上记住的网络；扫描、连接、忘记、信号显示照旧。
- **界面**：三语、深浅主题、搜索与排序、息屏时钟三种样式、OTA 暂停/删除、
  文件管理、备份还原、双系统。插件页与 webview 不在这一支上。

## 怎么确认装上了

```sh
adb shell dmesg | grep -i "recovery up"   # 应为 haotian 0.5.1.1
```

## This release in English

**Upstream 0.5.1, merged in.** This release brings `kirklin/skyward`'s 0.5.1
into this fork. What it changes on the phone:

**A backup restores into a data partition made afresh.** A restore used to
refuse a backup's data files whenever the data partition had been made again
since the backup — as a factory reset makes it. It restores them now: the
files go into the partition, the apps' folders in internal storage are
renumbered as the system running numbers them, and everything else lands where
it was (upstream `3179051`).

**A data partition the phone keeps unencrypted needs no key service.** A phone
whose data partition is kept in the clear used to reach for keymint anyway;
now it opens the partition directly and goes on without one (upstream
`3857f4c`, `7568a50`), and a data partition made afresh no longer depends on it
either (upstream `dc7f769`).

**Internal storage is an item of its own.** The files users keep under
`/data/media` are recorded as their own item in the manifest instead of being
mixed in with the data partition's (upstream `3179051`), so they can be
restored without the data partition's files.

**The secure element's driver is found as the phone describes it.** NXP's
weaver keeps its keys in its own secure element; the driver and the libraries
are read from the installed system's partitions now, so the recovery does not
give up on finding them (upstream `736ea54`).

**Engineering.** Upstream moved the workspace to what Rust 1.100 brings (the
never type, `trim_prefix`, `trim_suffix`, `bool::toggle`, `Vec::from_fn`), turned
on the workspace-wide `unused_dependencies` check, and fixed reading back a
hole in a super and counting an install's bytes twice. This fork keeps its own
pages (`crates/skyward-ui/src/app.rs`, `crates/skyward/src/ui.rs`) and its own
install engine; it takes upstream's engineering changes and the fixes above.
Upstream 0.5.1's 15-language pages, its page for choosing a time zone, its way
of flashing super, logical partitions and sparse images, and the REDMI K60 Pro
(`socrates`) are not on this branch. The fork's pages were moved onto the
`skyward-info`, `skyward-crypto`, `skyward-backup`, `skyward-config` and
`skyward-programs` interfaces upstream changed.

**The version is `0.5.1.1`.** The first three numbers are the upstream version
it is made on and the fourth is the fork's own patch level, going on `0.5.1.2`,
`0.5.1.3`. Being a four-part name like `0.3.1.2`, it is offered by the in-app
update check to phones running that build.

**Everything this fork's releases have, still here.** A raw super image as a
package of its own, written the way TWRP writes one; an install that cannot wait
for ever, with the script's output mirrored to the log and a report of where it
stalled; refusals at the unlock page in the page's own language; `avbctl`
covering both slots or neither; the back gesture's preview of the page under the
page shown in; a click of twelve to twenty-six milliseconds whose length follows
the slider; a remembered network joined by itself when the recovery starts;
three languages, both themes, the search and the sort, three faces for the
always-on clock, OTA pause and delete, the file manager, backups and two
installed systems.
