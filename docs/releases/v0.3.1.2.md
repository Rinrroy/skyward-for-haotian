Skyward 0.3.1.2 for the Xiaomi 15 Pro (`haotian`), made on the stock recovery
`OS4.0.0.19.XOBCNXM`.

Image: `skyward-v0.3.1.2-haotian-OS4.0.0.19.XOBCNXM.img`. Check it against
`SHA256SUMS`, then, with the phone in fastboot mode on the slot it runs from:

```sh
sha256sum --check SHA256SUMS
fastboot flash recovery skyward-v0.3.1.2-haotian-OS4.0.0.19.XOBCNXM.img
fastboot reboot recovery
```

## 这一版改了什么

### 1. 息屏时钟有了三种样式

息屏显示（AOD）以前只有一种面孔：日期、大字时钟、下面一条读数。这一版把
`guobaoji-122/skyward-for-aurora` 的息屏时钟切换搬了过来，设置页的息屏一节
多了一行「息屏时钟」，点一下换一种，三种轮着来：

- **数字**：原来的面孔，没变。
- **错位**：小时和分钟分在左右两边、上下错开，各是 150dp 的大字，日期在上、
  读数在下。
- **表盘**：一圈半径 104dp 的表盘，12 个刻度、四个整点数字、时针分针按当前时间
  摆，日期在上、读数在下。

样式跟着设置文件一起存，下次开机还是你选的那一种；面板下一次暗下去时画的就是新
面孔，不必等到下一分钟。三种面孔都照旧按分钟做防烧屏偏移，点亮面积也各有上限
（错位的两个大字是三者里最费的，仍只占玻璃的 5% 以内）。

### 2. 单独的关机页面删掉了

主页的系统列表里不再有「关机」一项，那一页（滑动关机）整页删除。关机仍然做得到：
重启页的滑动目标里就有「关机」，滑到头一样关机，所以少的只是一个入口，不是功能。

### 3. 并进了上游的两个修复

- 上游 `#56`：把模块刚生成的文件交出去（chown/chmod）之前，先等它真的出现，
  最多等 5 秒（`skyward-sys` 新的 `wait_file`）。模块加载慢一点的手机上，
  以前偶发的「文件不存在」不会再出现。
- 上游 `#52`：给 `dada` 那台机器用——第二颗 Peach 驱动单独加载、把安全元件的
  节点交给 system、按 Android 找库的路径去找密钥程序的库。这台手机（`haotian`）
  不用这些路径，但并进来以后两条线不会再各自漂。

### 4. 版本号的命名规则改了

从这一版起，这个 fork 的版本号是四段：`0.3.1.2`，前三段是它所在的上游版本
（Cargo 只认三段），第四段是这个 fork 自己的补丁号，往后就是 `0.3.1.3`、
`0.3.1.4`。About 页、开机日志、更新检查都显示这个四段的号。

应用内的更新检查也认四段了：它会读 `v0.3.1.2` 这样的标签，并且只和同样是四段的
发布比大小（三段的老发布不会被当成「更新」推给你）。`semver` 依赖因此去掉了。

这条规则的另一面要说清楚：还停在 `v0.3.2` 那种三段号的手机上，应用内**不会**收到
这一版的更新提示——三段和四段不互相比，装这一版得手动刷一次；从这一版往后
（`0.3.1.3`、`0.3.1.4`…）就又能正常收到了。

### 5. 装 ROM 时不再被另一个槽的镜像卡住

开着「保留本 recovery」装 ROM，安装会先看一眼两个槽的 recovery 分区里都是什么，好
知道装完之后该把本 recovery 写回哪个槽。以前只要其中任何一个槽的镜像读不出来——比如
另一个槽还留着系统自带的 recovery，它的 ramdisk 打包方式和这里认的几种都不一样——
整个安装就会失败，报 `hold this recovery from its partition: … read past a ramdisk
entry`。这一版把「读不出来」当成「那个槽里不是 Skyward」：安装照常往下走，本 recovery
该写回哪个槽就写回哪个槽，读不出来的那个镜像只在日志里记一行，说清它的 ramdisk 从哪
开始、多长、开头几个字节是什么，方便回头查。应用内更新 Skyward 自己也问同一句话，
所以那边也不会再被卡住。

## 这一版保留的东西

- **super 镜像**：认 liblp 几何头的整块 super 镜像可以直接刷，不问槽位、快照
  合并中拒绝；写前 discard、4 MiB 一次写、三窗口校验、本地文件直读，每 GiB 往
  内核日志写一行速率。
- **安装不会无限等**：脚本输出镜像进内核日志并在安装页显示；安静 30 秒报一次
  卡在哪；十分钟毫无动静就结束并把报告作为原因；`update-binary` 放在
  `/skyward/run`。
- **解密被拒时说界面语言**：weaver 的节流、错误密钥、重试都变成三种语言的句子。
- **AVB**：`avbctl` 一次改两个槽的 vbmeta（全成或全不成，flock 加写回校验）。
- **返回手势的预测式预览**：手指拉着的时候下面那一页跟着进来，每层留一张。
- **触感**：12–26 ms 的「嗒」，长度跟着强度滑块走，上限是满强度。
- **Wi-Fi**：开机自己连上记住的网络；扫描、连接、忘记、信号显示照旧。
- **界面**：三语、深浅主题、搜索与排序、OTA 暂停/删除、文件管理、备份还原、
  双系统。插件页与 webview 不在这一支上。

## 怎么确认装上了

```sh
adb shell dmesg | grep -i "recovery up"   # 应为 haotian 0.3.1.2
```

## This release in English

**Three faces for the always-on clock.** The always-on display used to wear one
face: the date, the clock in large digits, and a line of readings under it. This
release brings the clock switch from `guobaoji-122/skyward-for-aurora`: the
settings page's always-on section gained a row, `Clock style`, and each tap goes
on to the next of three faces.

- **Digits**: the face it had, unchanged.
- **Offset**: the hour and the minute on either side, one above the other, each
  150dp, with the date above and the readings below.
- **Dial**: a dial of 104dp radius with twelve marks, the quarter hours numbered,
  hands at the time, the date above and the readings below.

A face chosen while the panel dozes is drawn at once rather than at the next
minute, and the choice is kept with the rest of the settings, so the panel wears
the same face at the next start. Every face still drifts with the minute against
burn-in, and each is kept to a share of the glass: offset's two large fields are
the most any page lights, and are still under a twentieth of it.

**The power-off page of its own is gone.** The home page's system list no longer
has a power-off row, and the page behind it — slide to power off — is deleted.
Turning the phone off is still one of the destinations the restart page's swipe
offers, so what went is an entrance, not the function.

**Two upstream fixes, merged in.** Upstream `#56` waits for a file a module has
just made before it is handed over (up to five seconds, the new
`skyward_sys::wait_file`), so a phone whose modules load slowly no longer
occasionally meets a file that is not there yet. Upstream `#52` is for `dada`:
the second Peach driver loaded alone, the secure element's node handed to
system, and a key program's libraries looked for where Android looks for them.
This phone does not take those paths, but merged the two lines stop drifting
apart.

**The fork's versions are named differently now.** From this release the fork's
version has four parts: `0.3.1.2`, the first three being the upstream version it
is made on (Cargo takes three numbers and no more) and the fourth the fork's own
patch level, which goes on `0.3.1.3`, `0.3.1.4`. The About page, the boot log and
the update check all say the four-part name.

The in-app update check reads four-part tags now, and compares a build only with
releases named the same way, so the older three-part releases are never offered
as an update to it. The `semver` dependency went with it.

The other side of that rule is worth saying plainly: a phone still on a three-part
build such as `v0.3.2` is **not** told about this release, since the two kinds are
not compared, so getting here takes one flash by hand. From this release on
(`0.3.1.3`, `0.3.1.4` …) the in-app update works as before.

**An install no longer stops at a recovery image it cannot read.** With "keep this
recovery" on, an install looks at both slots' recovery partitions first, so that it
knows where to write this recovery back afterwards. It used to fail outright when
either of them held an image this build could not read — as when the other slot
still holds a stock recovery packed in a way this build does not know — with `hold
this recovery from its partition: … read past a ramdisk entry`. Such an image is
taken for one that is not Skyward now: the install goes on, this recovery goes back
where it belongs, and the image that could not be read is written into the log
once, with where its ramdisk starts, how long it is, and the bytes it starts with.
The in-app update of Skyward itself asks the same question of the same slots, so
it is no longer stopped there either.

**Everything this fork's releases have, still here.** A raw super image as a
package of its own, written the way TWRP writes one; an install that cannot wait
for ever, with the script's output mirrored to the log and a report of where it
stalled; refusals at the unlock page in the page's own language; `avbctl`
covering both slots or neither; the back gesture's preview of the page under the
page shown in; a click of twelve to twenty-six milliseconds whose length follows
the slider; a remembered network joined by itself when the recovery starts;
three languages, both themes, the search and the sort, OTA pause and delete, the
file manager, backups and two installed systems.
